# 口算 PK 辅助原型

这是一个纯 Android、Kotlin 编写的 MVP。它只在用户主动开始后工作：无障碍服务读取目标应用当前窗口的 `text` 与 `contentDescription`，解析独立数字节点或 `8?7` 形式的组合题，比较大小，再按指定策略点击或在手写区绘制关系符号。

项目不包含 Root、Hook、抓包、联网或 OCR。题目始终来自界面节点；Android 11 及以上仅在作业帮全自动首批开始前短暂分析屏幕小区域的像素变化，不保存或上传截图。

> 本项目仅用于 Android 无障碍服务、界面节点识别和自动化技术研究。使用者应遵守相关应用的用户协议和当地法律法规，并自行承担账号限制、数据异常等风险。

关键词：口算 PK、作业帮口算 PK、小猿口算 PK、Android 无障碍、AccessibilityService、Kotlin、XiaoYuanKouSuan、Zuoyebang。

## 已实现

- 原生 Kotlin + Android Gradle Plugin 项目，无第三方运行库。
- 同一 APK 支持“小猿搜题”和“作业帮”两套独立预设，可在主界面一键切换。切换时会先安全停止当前任务，再载入目标包名、扫描范围、手写路径和速度参数。
- 作业帮模式保留旧版识别与笔画：默认包名为 `com.baidu.homework`、`com.zybang.parent`，使用旧扫描区域和单短笔画；每批最多预读 10 题并使用计划总时长 `895 ms` 的批量手势。启动时会锁定本局完整题序，后续即使 WebView 在答题过程中重排或重复节点，也只按真实题号从原题序续答。若页面题数超过 10，会自动继续下一批，直到页面显示的总题数完成。
- 主界面显示无障碍/通知权限、服务连接、运行状态、当前包名、左右值、关系、处理/错误计数和滚动日志。
- 运行时只处理配置的目标包，默认目标为小猿搜题 `com.fenbi.android.solar`；应以你手机上的实际包名为准。
- 同时检查每个节点的 `text` 和 `contentDescription`。
- 按屏幕比例配置扫描上下边界、左/右区域和最大纵向差，从多组候选中选择最对称、最对齐的一对。
- 答案模式：在手写区绘制 `<` / `=` / `>`、点击较大数字、点击较小数字、点击固定关系按钮区域。
- 默认模式为手写：以屏幕约 `(0.50, 0.72)` 为中心，采用单笔方向手势输入 `<` / `=` / `>`；中心、宽高和笔画时长均可配置。
- 若小猿搜题页面预加载整组题，极速模式会每次读取最多 10 题，再把单笔关系手势排入同一个手势序列。默认单笔 `40 ms`、起点间隔 `95 ms`，每批 10 题计划总时长 `895 ms`；20 题及更长比赛会在确认实际题号后继续下一批。
- 小猿搜题当前页面只暴露“当前题 + 下一题”时，服务会自动退出整局批量等待，改走低延迟逐题模式。节点数字前后的普通空格、不间断空格都会先规范化；默认识别区域只覆盖上方当前题，避免误答半透明的下一题。
- 高段位页面可能把当前题暴露成不含问号的 `5　15` 单节点；小猿模式会把同一节点中由空格分开的两个整数识别为左右值。该兼容规则不用于作业帮。
- 小猿搜题采用常规手写识别，`<`、`>`、`=` 均按完整的两笔符号绘制；比赛计时器兼容 `00:17`、`03:40` 等分钟秒格式。
- 逐题状态机读取页面真实的 `当前题/总题数`（例如 `1/10题`、`1/20题`）作为完成进度：提交手势后先等待题号增加，再等待新题节点稳定；短暂残留的旧题不会重复计数，未被接受的手势会在超时后有限重试。
- 小猿速度优化模式将 `<`、`>` 作为一条连续折线完成，只有 `=` 使用两次独立落笔；当前单笔为 `30 ms`。每题必须确认题号前进和新题节点刷新，再经过短暂事件安静窗口才会落下一笔，避免画板尚未清空时发生笔迹重叠。
- 切题保护默认从 `50 ms` 开始；题号前进后若仍读到上一题，会等待旧节点真正消失（最长 `650 ms`），避免重复落笔。20 题及以上页面的逐题手写最低使用 `60 ms`，兼容高段位更严格的识别；同一题连续未确认时只允许一次补画，之后安全停止，避免墨迹无限叠加。
- 小猿模式不使用固定题数上限，以页面给出的总题数为准并答到页面结束。如果用户已经手动答过若干题，服务会读取实际进度，跳过 WebView 中缓存的已答题，只处理剩余题目，避免整组答案错位。
- 悬浮“开始”可以在倒计时或开场动画前提前按下。小猿模式会先进入待命，只在比赛计时器和同一首题连续两次同时出现后才解锁第一笔；提前启动额外等待 `50 ms` 对齐题面，避免手势相对开场动画整体前移而发生笔迹重叠。高段位页面不再暴露旧版“手写区”节点，因此不把该文字作为硬条件。比赛已经开始后再按只需 `10 ms` 同步。
- 极速模式会等待开场状态；开场等待、单笔时长和两笔起点间隔均可配置，设置页会阻止总手势时长超过 `1000 ms`。
- 关闭极速模式后仍可使用逐题回退模式；逐题手写默认保留较长冷却，便于定位兼容性问题。
- 点击策略：优先点击可点击节点祖先，失败后用无障碍手势点击节点中心；也可强制只用坐标。
- 无障碍服务连接后，屏幕右侧显示“开始/停止”。按住按钮可拖动；拖到左右边缘会收缩成小箭头，作答状态保持不变，轻点箭头只展开而不会停止。它使用无障碍悬浮层，不需要另授普通悬浮窗权限。
- 主界面提供“全自动模式”开关，默认关闭。开启后服务保持待命，仅在目标题目页检测到比赛计时器和可用题目时自动启动。作业帮屏幕上真正可见的“题目数量”前置弹窗、“本轮 PK 目标 / 比谁快”开场动画、`READY`、`GO` 及胜负结算弹窗，即使仍暴露背后的旧计时器和题目，也会被作为硬门控。由于当前作业帮 WebView 在动画层下提前暴露题组、且 READY/GO 文字节点并非每局都可读取，Android 11 及以上会在预读首批后短暂采样屏幕中央区域：只有观察到明显画面变化、当前画面偏离首帧并连续稳定，才提前提交；截图只在内存中提取少量像素特征，随后立即释放。画面证据不足、系统不支持或截图失败时，仍从预读完成起等待 `1.9 s` 安全兜底。接管已经有答题进度的比赛不启用这段首局门控。批量提交后继续读取真实题号，不再立即停止。最后一批如果暂时仍显示旧题号，会只等待结算而绝不重复整批；只有读到真实部分进度时才从锁定题序续答。最后一题由题号完成、结算弹窗或答题页退出确认后锁住旧题页；只有结算状态稳定保持 `500 ms` 并进入下一局，或确认题序已经换新，才会重新启动。作业帮全自动开启时，悬浮按钮“停止”只暂停当前局并进入下一局待命，不再悄悄关闭全自动开关；主界面开关仍是永久开启或关闭全自动的唯一入口。小猿仍使用原有题号重置锁。
- 可选低优先级通知，带“立即停止”动作。
- 防连点：连续稳定读取、点击冷却、回答后等待题目消失或变化、相同题面不重复点击。
- 安全限制：单次最大处理数、最长运行时长、离开目标应用超时、连续点击失败上限、节点扫描上限。
- `ScreenshotQuestionReader` 题目识别接口仍未实现，当前不调用 OCR；轻量截图仅用于作业帮开场状态判断。

## 首次授权

1. 打开“口算 PK 助手”，先在主界面选择“小猿搜题”或“作业帮”。
2. 点击“无障碍设置”。
3. 在“已下载的应用”或“已安装的服务”中找到“口算 PK 节点读取服务”，打开它并确认系统警告。
4. 返回主界面，确认“无障碍授权”和“服务连接”均显示已授权/已连接。
5. 返回小猿搜题，确认屏幕右侧出现“开始”开关；需要运行时手动点一下，运行中可点“立即停止”。
6. Android 13 及以上可选授予通知权限，用于通知栏紧急停止入口。

部分 Android 13+ 设备会禁止侧载应用开启无障碍服务。此时进入系统的应用详情页，打开右上角菜单，选择“允许受限设置”，再回到无障碍设置。不同厂商名称可能略有差异。

## 先确认实际包名

打开小猿搜题并停在口算 PK 页面，在 PowerShell 中运行：

```powershell
adb shell dumpsys window | Select-String 'mCurrentFocus|mFocusedApp'
```

输出通常包含类似：

```text
com.example.package/com.example.package.SomeActivity
```

斜杠前面就是包名。也可以用：

```powershell
adb shell pm list packages | Select-String 'homework|zybang|zuoye'
```

把实际包名填到应用的“配置包名、识别区域与点击策略”页面。服务配置 XML 没有写死包名，而是在运行时严格按这里的列表过滤，因此改包名不需要重新编译。

## 用 uiautomator dump 定位节点

1. 先点悬浮开关“立即停止”，在手机上打开一道“比大小”题并保持画面不动。
2. 在电脑运行：

```powershell
adb shell uiautomator dump /sdcard/window.xml
adb pull /sdcard/window.xml .\window.xml
```

3. 快速搜索可能的数字与属性：

```powershell
Select-String -Path .\window.xml -Pattern 'text="|content-desc="|resource-id="|bounds="|clickable="true"'
```

部分手机（本次实测的一加机型即如此）执行 `uiautomator dump` 会让无障碍服务短暂解绑。定位完节点后，如屏幕开关消失，请到系统无障碍设置里把本服务关闭再打开一次。

重点检查左右数字是否以如下任一形式出现：

```xml
text="37"
content-desc="37"
```

同时记录对应节点的：

- `package`：填入应用配置的目标包名。
- `bounds="[x1,y1][x2,y2]"`：数字或可点击区域的位置。
- `clickable="true"`：节点能否直接执行点击。
- `resource-id` 与 `class`：用于人工确认节点身份；当前 MVP 不依赖固定资源 ID。

如果 `/sdcard/window.xml` 不可用，可改为：

```powershell
adb shell uiautomator dump /data/local/tmp/window.xml
adb pull /data/local/tmp/window.xml .\window.xml
```

查看屏幕尺寸：

```powershell
adb shell wm size
```

把 bounds 转成配置比例的方法：

```text
中心 X 比例 = ((x1 + x2) / 2) / 屏幕宽度
中心 Y 比例 = ((y1 + y2) / 2) / 屏幕高度
```

例如 1080×2400 屏幕上的中心点 `(270, 1200)`，比例约为 `(0.25, 0.50)`。

## 建议测试流程

小猿模式默认启用极速分批，但不限制整局题数；每个系统手势批次最多 10 题。设置里的“单次最多处理题数”只作为作业帮或无题号页面的备用安全值。

1. 在配置页填入实际包名。
2. 如果当前“比大小”题需要在手写区输入关系符号，选择“在手写区绘制 <、=、>”；若要求点数字或按钮，再选择相应点击模式。
3. 进入目标题目页或匹配开场后，手动点屏幕右侧开关“开始”。工具预读整局并等待开场时机，完成或达到安全上限后自动停止。
4. 观察悬浮窗或主界面是否显示正确的 `左值 关系 右值`。
5. 第一次最好手动准备停止：悬浮窗、通知栏或主界面都能立即停止。
6. 测完检查日志。日志会记录所选关系、点击值/坐标和失败原因。

## 常见调整

### 找到错误的数字

- 收紧“上边界 Y 比例”和“下边界 Y 比例”，只覆盖题目区域。
- 把左最大 X 与右最小 X 分别向屏幕两侧移动，排除中间的题号、倒计时或分数。
- 保持默认正则 `^\s*(-?\d{1,6})\s*$`，它只接受整个节点文本都是整数的情况。
- 题目若暴露为 `8?7`，默认组合正则会把第 1、2 个捕获组解析为左右数字。多个预加载题同时存在时，读取器选择题目区域内最靠上的组合题。
- 如果节点文本类似 `数字 37`，可改成 `^数字\s*(-?\d{1,6})$`。

### 识别正确但不点击

- 查看 dump 中数字节点或其父节点是否 `clickable="true"`。
- 保持“优先点击节点，失败后点坐标”；若节点动作返回成功但界面无响应，改成“只按坐标点击”。
- 检查数字 bounds 的中心是否真在按钮可点击区域。
- 固定关系按钮模式需校准三处 X 比例和共用 Y 比例。

### dump 中完全没有左右数字

这通常说明题目由 Canvas、自绘 View、图片或游戏渲染层绘制。当前版本会在日志中报告“未形成左右配对”，不会偷偷截图，也不会自动切换到 OCR。

后续可实现 `automation/ScreenshotQuestionReader.kt`：由用户明确授权 MediaProjection，截取固定题目区域，OCR 后返回统一的 `QuestionReadResult`。MVP 中这个接口故意保持不可用。

## 代码结构

```text
app/src/main/java/com/example/kousuanpkassistant/
├─ automation/
│  ├─ AccessibilityNodeQuestionReader.kt  # 遍历节点、抽取候选、左右配对
│  ├─ ClickDispatcher.kt                  # 节点点击与手势回退
│  ├─ QuestionReader.kt                   # 节点读取接口与扫描生命周期
│  └─ ScreenshotQuestionReader.kt         # 截图/OCR 占位接口
├─ data/ConfigRepository.kt               # SharedPreferences 配置
├─ model/                                 # 配置、关系和题目模型
├─ service/
│  ├─ KousuanAccessibilityService.kt      # 事件、状态机、去重和安全限制
│  └─ OverlayController.kt                # 屏幕开始/停止开关
├─ receiver/SafetyStopReceiver.kt         # 通知栏停止动作
├─ state/AutomationStateStore.kt           # 主界面状态与内存日志
└─ ui/                                    # 主界面与配置界面
```

代码默认值集中在 `model/AutomationConfig.kt`；大多数参数也可直接在应用配置页修改并持久化。

## 限制与使用边界

- 无障碍节点读取是否可行，取决于目标应用是否把题目暴露到 Android 的可访问性树中。
- MVP 只用启发式位置配对，不根据特定版本的资源 ID 写死规则。界面改版后可能需要重新校准区域。
- 回答后必须观察到题面消失或签名变化才会重新点击；极少数连续两题数值和位置完全相同、且中间没有空白状态的情况会被安全地跳过。
- 仅在自己的设备和测试账号上使用，并遵守目标应用的使用条款。自动参加排名或对战可能被视为不公平行为。
- 无障碍服务属于高敏感权限。此原型没有网络权限，也不保存窗口内容；如果计划分发或上架，需要重新评估隐私披露和应用商店对无障碍 API 的政策要求。
